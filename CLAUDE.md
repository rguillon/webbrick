# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A brick breaker game whose game logic is pure Python, running in the browser through Pyodide (v0.27.2, loaded from the jsDelivr CDN). The game has no build step and no Python dependencies. The repo started from a uv project template (`pyproject.toml`, `Makefile`, tox, mkdocs, GitHub workflows). The game is the `webbrick` package in `src/webbrick/`.

## Commands

```bash
make run                     # uv run python -m http.server 8000 --bind 127.0.0.1, serving the repo root
make run PORT=9000           # HOST= / PORT= override
make install                 # uv sync + pre-commit hooks
make check                   # lock check, pre-commit, ty, deptry
make test                    # pytest with coverage (tests/), must stay at 100% (fail_under)
uv run ruff check src && uv run ruff format src
```

`make check` runs ruff from pre-commit, with a pinned version that can differ from the one in `.venv`. Trust the pre-commit result.

## Tests

- `tests/conftest.py` installs fake `js` and `pyodide.ffi` modules in `sys.modules` before anything imports `webbrick`. It provides `FakeJs` (any attribute or call returns another fake), `FakeWindow` (records listeners, dict-backed `localStorage`), `FakeDocument` and `FakeKey`. Its fixtures are `window`, `game` (started, seeded RNG, on the menu), `playing` (level 1, ball launched, no bonus bricks) and `press` (sends key events through the bound listeners).
- **Each test has exactly one assert.** Put shared setup in a fixture, or in a small helper like `tick()` or `fire_once()`, and give each outcome its own test. Fixtures can share state: a test that requests `arena` and `boosted` gets the same `Game`. Parametrize over data such as levels or colour mixes instead of looping. Comparing a tuple counts as one assert when it checks one fact, such as a position `(x, y)` or `(state, level)`. Rendering smoke tests (`test_every_state_renders`) have no assert.
- Ruff applies to tests too. Annotate every test and fixture argument. Import `Game` and the conftest fakes under `TYPE_CHECKING` only. Fixture docstrings must start in the imperative mood ("Return …", "Clear …").
- Tests drive the game through its private steps (`_update`, `_confirm`, `_collect`, …) and call `frame()` for rendering. To exercise the game by hand, reuse the same stubs: put them in `sys.modules`, add `src` to `sys.path`, then `from webbrick.main import main; game = main()`.

You can't open `index.html` from disk (`file://`) because the page `fetch`es the game's Python modules, so always go through `make run`. The first load needs internet access to download Pyodide.

## Architecture

There is no custom server. `http.server` serves the repo root, so URLs mirror repo paths: the page is `/index.html` and the modules are `/src/webbrick/*.py`.

- **`index.html`** (repo root, outside the sources) holds the only JavaScript, and it's just a bootstrap: it calls `loadPyodide()` and fetches every file listed in its `MODULES` array from `src/webbrick/` (`PACKAGE` in the script), in parallel. It writes them into Pyodide's virtual filesystem at `/home/pyodide/webbrick/`, then runs `from webbrick.main import main; game = main()` and reports progress or errors in `#status`. **When you add, rename or remove a module in `src/webbrick/`, update `MODULES` too**, or the browser import fails. The page is a full-viewport flex column (header, `#stage`, controls panel). The canvas is absolutely positioned inside `#stage` so that its size never changes the stage's own size, which keeps the resize handling free of feedback loops.
- **`src/webbrick/`** is the game, a Python package that runs **inside Pyodide only**. It imports `js` and `pyodide.ffi`, so it can't be imported under regular CPython without stubs (see Tests). `pyproject.toml` tells `deptry` (DEP001) and `ty` (`allowed-unresolved-imports`) to accept those imports. Ruff applies, using the project config, and `Any` isn't allowed in annotations (ANN401). Annotate JS objects (events, canvases, 2D contexts) as `JsProxy`, imported from `pyodide.ffi` under `TYPE_CHECKING`, because the test stubs don't define it. Use one `random.Random()` instance per module (with a single `# noqa: S311`) instead of `random.*` module functions. Modules use relative imports, with one class per file:
  - `config.py`: all layout, tuning and key constants. `levels.py`: `LEVELS` data. `font.py`: `GLYPHS`, a 5×7 bitmap font.
  - `brick.py`: `Brick` plus `build_bricks()`. `ball.py`: `Ball` (several can be in play), which moves itself in `update()` and is told about hits through `bounce_x()`/`bounce_y()`/`bounce_paddle()`; it owns its `speed` (a get/set property over the heading), its `color` (the trail colour, from `FireBonus`) and its `fire` flag. `powerup.py`: `PowerUp`, a falling bonus capsule. `bonus.py`: the `Bonus` power-up classes (`FireBonus`, `SpeedBonus`, `GunBonus`, `MultiBonus`, `LifeBonus`) and the `BONUSES` registry. `particle.py`: `Particle`, one spark of a burst (flies, falls, burns out). `particles.py`: `Particles`, the collection the game owns as `game.particles` (`burst()`, `update()`, `draw()`, `clear()`; it is iterable and sized, and spawns from the game's `rng`). `sprite.py`: `Sprite` plus `offscreen()` and `snap()` (rounding a logical coordinate to the pixel-art grid). `storage.py`: `localStorage` helpers.
  - `graphics.py`: the procedural pixel-art `make_*` sprite painters, `block()`, `pixel_box()`, `paint_text()` and `mix()`. It has no class.
  - `game.py`: the `Game` class. `main.py`: `main()`, which creates the game, binds input and starts `requestAnimationFrame`.
  - The dependency direction is `config`/`levels`/`font` → `ball`/`bonus`/`brick`/`particle`/`particles`/`powerup`/`sprite`/`storage` → `graphics` → `game` → `main`. Keep it acyclic. `bonus.py` imports `Game` only under `TYPE_CHECKING`; a `Bonus` is handed the game instance by `Game`, which keeps the list `game.bonuses` of the bonuses still running. `particles.py` imports `particle.py` and spawns with the `random.Random()` the game passes into `Particles(rng)`.
  - Every Python callable handed to JS (event handlers, the frame callback) is wrapped in `create_proxy`, and a reference is kept (`self._proxies`, `self._frame_proxy`) so the proxies aren't garbage-collected. New callbacks must follow the same pattern.
  - Input is keyboard-only (no mouse handlers) and is bound on `window`. Held keys are normalized into `self.held` (`"left"`/`"right"`, plus `"fire"` for Space/Enter) and cleared on `blur`.
  - The state machine is `self.state` ∈ `menu | ready | playing | paused | over | cleared | victory`. `_confirm()` (Space/Enter) holds the per-state action. `_start_run()` resets score and lives, while `_start_level()` only loads bricks, so a run carries over between levels.
  - Levels are ASCII layouts in `LEVELS` (`.` empty, `1`–`3` hit points, `X` unbreakable steel), `BRICK_COLS` characters per row and at most 8 rows (the menu preview and the HUD spacing assume that). The menu shows `CARDS_PER_PAGE` level cards at a time and pages follow the selection; digit quick start only reaches levels 1–9. A level is cleared when no breakable bricks remain. `_start_level()` marks `BONUS_CHANCE` of breakable bricks with a `bonus` kind (a `POWERUPS` key). Breaking one drops a capsule that falls at `POWERUP_FALL_SPEED`; the paddle catches it (`_collect()`), which starts the matching `Bonus` from `bonus.py` in `game.bonuses` (collecting a kind again replaces the running one, never stacks). `Bonus.apply(game, dt)` puts the effect on the game for another slice of time and returns whether the bonus is over; `_update_bonuses()` applies them all and drops the finished ones, and `Game.has_bonus(kind)` is how the rest of the game asks whether one is running (the cannon check, for instance). Bonuses only touch the game through its accessors: `split_balls()`, `set_speed_mult()`, `set_balls_fire()` and `award_life()`. Each capsule kind has its own class: `multi` splits the ball into three (the new balls inherit the fire of their source), `pierce` (`FireBonus`) lights every ball on fire for `PIERCE_TIME` — each `Ball` carries that `fire` flag, which makes it smash through breakable bricks without bouncing and paints its trail with `Ball.FIRE_COLOR` — `life` hands out a life through `award_life()` (or points at the life cap), `speed` (`SpeedBonus`) multiplies ball speed by `SPEED_BOOST` for `SPEED_TIME` — restoring it when the bonus ends — and `gun` gives the paddle cannons for `GUN_TIME`: while `"fire"` is held, volleys of two bullets are fired every `BULLET_INTERVAL`, and each bullet takes one hit point off the first brick in its path (`_update_bullets()`). A life is lost only when the last ball falls out, and `_reset_ball()` drops falling capsules, running bonuses and every ball's fire. Cleared levels persist in `localStorage` (`STORAGE_KEY`, still `"brickbreaker.cleared"`; renaming it would lose players' saved progress).
  - The user requires that all graphics are generated in code, with no image assets, in a pixel-art style. Sprites are painted on a grid of `PIXEL`×`PIXEL` logical px "art pixels" (`block()` fills them), so sprite sizes and on-grid positions should be multiples of `PIXEL`; moving objects are drawn at `snap()`ped positions. There are no gradients, curves or `shadowBlur`: shading is done with flat colour rows, glows with a faint one-pixel ring. All text goes through `Game._text()`, which blits cached `make_text()` sprites of the bitmap font (upper-cased, `?` for missing glyphs, so add a glyph to `font.py` before using a new character) at an integer `size`. Sprites (background, bricks keyed by `(color, hp, solid, has_bonus)`, paddle, ball, capsules, menu previews, text) are pre-rendered once into off-screen canvases and blitted with `drawImage`. This keeps the number of Python→JS FFI calls per frame low, so follow the same pattern for new visuals.
  - Resolution independence: the game always works in `WIDTH`×`HEIGHT` (480×600) logical units. `_resize()` (run at startup and on window `resize`) fits the canvas to `#stage` with the same aspect ratio. It sets the backing store to CSS size × `devicePixelRatio`, and `_draw()` starts with `setTransform(self.scale, …)` and turns `imageSmoothingEnabled` off. Sprite canvases have their logical size (`offscreen(w, h)` returns a `Sprite`) and are scaled up with nearest-neighbour sampling, so they are built once in `_build_sprites()` and never re-rendered on resize. Always blit through `Sprite.draw()`, which takes logical sizes, never call `drawImage` directly.
  - Physics is time-based. `frame()` clamps `dt` to 1/30 s, and `_update()` splits ball motion into sub-steps of at most `MAX_BALL_STEP` px so the ball can't tunnel through bricks. Each sub-step is `Ball.update()` (the ball moves itself and remembers its trail) followed by `_resolve_collisions()`, where the game only signals what the ball ran into: `bounce_x()`/`bounce_y()` for walls and bricks (one brick per step, bouncing on the axis with the smaller overlap), `bounce_paddle()` for the paddle, and dropping the ball once `Ball.fallen` says it left at the bottom.
  - All layout and tuning values are constants in `config.py`. Brick positions are computed once in `build_bricks()`.
  - `_set_status()` mirrors the game state into the page's `#status` element.
